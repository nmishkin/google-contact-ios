# google-contacts-ios

A native SwiftUI client (iOS/iPadOS/macOS) for full-fidelity access to Google Contacts data — labels, groups, custom fields, and multiple typed emails/phones/addresses — that Apple's Contacts app normally flattens or drops when synced from a Google account.

See the design spec ([docs/superpowers/specs/2026-09-19-google-contacts-app-design.md](docs/superpowers/specs/2026-09-19-google-contacts-app-design.md)) and implementation plan ([docs/superpowers/plans/2026-09-19-google-contacts-app.md](docs/superpowers/plans/2026-09-19-google-contacts-app.md)) for details.

The Xcode project is `GoogleContacts.xcodeproj`, generated from `project.yml`; app code lives under `App`, with shared logic in the `GoogleContactsKit` Swift package under `Packages`.

## Building and installing

`GoogleContacts.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` and is gitignored — run `xcodegen generate` after changing `project.yml`, or just use the scripts below, which do this for you. Regeneration needs `GOOGLE_CLIENT_ID` and `GOOGLE_REVERSED_CLIENT_ID` set (see `.env.local`) so it can fill in `Info.plist`'s OAuth values; without them, `xcodegen generate` writes unexpanded `${...}` placeholders instead.

- **`./build-and-install.sh`** — builds the macOS app (Release, ad-hoc "Sign to Run Locally" signing, no Apple Developer account needed) and copies it to `/Applications`.
- **`./build-and-install-ios.sh`** — builds and installs the iOS app to a connected physical iPhone. Requires:
  - An Apple Developer account. The team ID is set in `project.yml` (`DEVELOPMENT_TEAM[sdk=iphoneos*]`), scoped to real-device (`iphoneos`) builds only so it doesn't affect the macOS or simulator builds.
  - The iPhone connected by cable, unlocked, with **Developer Mode** on (**Settings → Privacy & Security → Developer Mode**, requires a reboot to take effect) and paired with this Mac (opening Xcode once and checking **Window → Devices and Simulators** helps confirm pairing).
  - An Apple ID signed into Xcode (**Xcode → Settings → Accounts**) with access to the team.
  - The script auto-detects the first connected physical iPhone via `xcrun devicectl list devices` and installs with `xcrun devicectl device install app`.
  - On first launch, iOS blocks the app as an "Untrusted Developer" — trust it under **Settings → General → VPN & Device Management**, then relaunch.
  - A development-signed install like this only runs while Developer Mode stays on; turning Developer Mode off blocks it from launching until turned back on. TestFlight/App Store builds (below) don't have this restriction.

## Publishing to TestFlight

### First time
1. **Register the bundle ID**, if it isn't already (check under **developer.apple.com/account → Certificates, Identifiers & Profiles → Identifiers**): **+** → **App IDs** → **App** → Bundle ID type **Explicit**, value `com.mishkin.GoogleContacts-iOS`, no capabilities needed.
2. **Create the app in App Store Connect**: **appstoreconnect.apple.com → My Apps → + → New App**. Platform iOS, pick the bundle ID from the dropdown (only shows up once step 1 is done), any unique SKU.

### Subsequent times
1. **Archive and upload**: open `GoogleContacts.xcodeproj` in Xcode, scheme **GoogleContacts_iOS**, destination **Any iOS Device (arm64)** (archiving needs this, not a simulator or a specific plugged-in device). **Product → Archive**. When the Organizer opens, **Distribute App → TestFlight & App Store Connect → Upload**. Automatic signing handles the distribution certificate/profile. Apple then processes the build server-side (usually 5-30 minutes) before it appears under the app's **TestFlight** tab at the app-specific page under **appstoreconnect.apple.com/apps**.
2. **Export compliance**: the first build for the app prompts for an encryption-usage answer — this app only uses standard HTTPS, so answer "No" to using proprietary encryption.
3. **Test information**: a short description of what to test is required before any tester (including yourself) can install a build.
4. **Add yourself as a tester** under the app's **TestFlight** tab: create a group (e.g. "Internal Testers") under **Internal Testing**, add your Apple ID to it, and add the build to that group. Internal testing has no App Review step — the build is installable as soon as it finishes processing. (External testers would need a quick Beta App Review first.)
5. **On your iPhone**:
   - Install the **TestFlight** app from the App Store, if it isn't already there.
   - Open TestFlight and sign in with the same Apple ID used in step 6.
   - The app should show up directly in TestFlight's list. If it doesn't appear after a minute or two, check email (including spam) for a "You've been invited to test..." link from Apple and tap it — accepting the invite link is sometimes needed even for internal testers, and it opens straight into TestFlight.
   - Tap the app, then **Accept** if prompted, then **Install**.
